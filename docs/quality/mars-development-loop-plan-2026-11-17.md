# Mars 开发助手闭环计划

日期：2026-11-17。状态：产品方向已确认，待实施。

## 1. 用户确认与目标

用户已确认：

- 主方向：修改现有项目 → 运行测试 → 根据错误修正 → 展示 Diff 和结果。
- 自主范围：在选定项目中编辑代码、运行已有测试和构建。
- 确认边界：安装依赖、Git 提交或推送前询问用户。本次选择是计划授权，不是现在安装依赖或提交代码的授权。
- 验收候选：现有项目修 bug、增加小功能、跨文件重构。具体项目、需求和用例须在真实评测前固定，不能把候选类别写成已确定或已完成的任务。

成功标准是用户能核对实际修改和验证证据，并知道任务完成、失败或需要决定的具体原因。工作台数量、测试总数和工具调用次数不是交付成功标准。

## 3. 本轮执行与证据合同

1. 项目根沿用接纳时记录的 workspace。切页面、切会话或之后改绑不改变已接纳任务的根。
2. 修改前读取相关代码和项目说明，记录验收条件与已有测试入口；不把框架猜测当成项目配置。
3. 测试失败时，把退出码和相关错误反馈给模型；模型修改后再运行受影响测试。沿用现有工具、执行预算和取消路径。
4. 普通测试失败不等同于进程故障；网络不可达、环境缺失和代码错误分别记录。若需要安装依赖，暂停该操作并呈现具体命令、目录和目的供用户确认，不静默安装或声称测试通过。
5. 不把任意 shell 命令当作“已有测试/构建”。授权判断落在现有执行边界；提示词说明不能替代该边界。明确禁止操作继续有效，未知外部副作用不盲目重放。
6. 终态继续由现有 Runtime/Verifier 发布；UI 不根据退出码单独推导 Run COMPLETED。编译通过也不自动等于用户需求全部满足。
7. 项目可能已有未提交修改。Diff 必须区分任务开始时已有内容与本轮变化，不把整个 `git diff HEAD` 冒充 Agent 的贡献；新建未跟踪文件也必须可见。
8. 若用户同时编辑导致无法可靠归属，明确显示“归属无法确认”，不回退、不覆盖、不伪造任务专属差异。
9. 保留现有文件敏感内容投影和路径边界；Diff/日志新入口不能绕过它们展示原始密钥。

## 4. 工单

### MC-01 / P1 — 固定开发闭环的失败用例与测量口径

范围：隔离项目 fixture、Service/真实 sidecar 入口测试、候选任务验收说明。

- 准备三个小型仓库 fixture，依赖预装或无需外部依赖：修 bug、小功能、跨文件重构。
- 每个 fixture 明确输入、已有文件、允许修改范围、验收命令和预期结果。包含一个已有用户修改及一个未跟踪文件场景。
- 首先用假 Provider 驱动现有工具链执行，记录第一处真实断点；不要预先假定必须修改 FailurePolicy。
- 统一记录：任务是否满足验收、人工介入次数、工具错误、复测次数、耗时。token/费用仅在 Provider 提供且可验证时记录，未知不显示为零。

验收：从 Service 或真实 sidecar 入口观察实际文件与命令结果，至少一例先失败后通过。不能只替换成功摘要、注入产物行或测试一个纯函数就宣称链路闭环。

### MC-02 / P1 — 自主验证授权与 coding 指令对齐

依赖：MC-01。范围：现有 effect authorization、policy、工具目录和 coding 技能。

- 将“选定项目中自主编辑并运行已有测试/构建”的用户意图沿现有授权链传递到实际 shell 工具。
- 同步 coding 技能说明，明确何时可以自主验证、何时必须请求安装/提交/推送授权。
- 审核当前 shell 路径是否能执行上述确认边界；复用现有审批能力补齐实际缺口，不新增三档模式或第二套权限配置。
- 项目测试脚本是否产生外部效果由现有策略处理，不能因为命令叫 test/build 就绕过既有禁止效果。

验收：同一假 Provider 流程中，编辑与本地测试可执行；依赖安装、commit、push 未获确认前不执行；显式 COMMAND_EXECUTION 禁止仍生效。测试须检查执行器确实未收到被阻止的命令。

### MC-03 / P1 — 工具失败后的最小自主修正链路

依赖：MC-01、MC-02。范围：Agent Loop、工具结果投影及被用例证明需要调整的 Runtime 边界。

- 跟踪测试命令失败是否完整回到模型；若错误丢失、截断关键信息或直接结束循环，在责任层修复。
- 保持“读取错误 → 相关修改 → 复测”的单一执行路径，不另建独立修复 Agent 或通用恢复框架。
- 沿用现有预算、进展约束和取消机制。重复失败不伪造成功；耗尽预算时返回已完成工作、失败证据和下一步所需信息。
- 未复现普通错误进入错误恢复层之前，不扩充全局 retry/replan 白名单。

验收：假 Provider 经真实工具先制造失败，再读取反馈修正，实际测试通过；无法修复的一例保留失败原因并停止；取消执行后不继续写文件或启动下一条测试命令。

### MC-04 / P1 — 任务改动预览与验证记录

依赖：MC-01，可与 MC-02/03 分批推进。范围：现有 Run 证据、Service DTO、Mars 结果展示。

- 对本轮需要修改的文件建立任务前基线，记录可核验的任务前后内容/摘要；先复用现有文件效果与 artifact 事实，补足缺失字段即可。
- Mars 展示新增、修改、删除文件及对应差异；明确区分原有用户修改和本轮变化。执行前基线在重开历史 Run 时仍可解释。
- 测试记录含实际命令、执行目录、退出结果、相关输出和所属 Run。失败定位可以打开对应文件；不将模型口述当命令执行证据。
- 首版不执行自动 stash/reset/commit，不提供无法证明安全的一键回退。非 Git 项目如无法提供完整 Diff，应明确能力范围，不能自动初始化仓库。

验收：隔离 Git 仓库预置用户修改，Agent 修改另一处后预览准确；新增未跟踪产物可见；不能归属的并发修改显式标注；敏感内容按现有保护规则投影；失败测试不显示成功徽标。

### MC-05 / P1 — Mars 前端实际交互回归

依赖：MC-03、MC-04。范围：Mars rail、任务状态、结果面板与必要的组件测试支持。

- 对首页发起、成功后进入记录、失败保留输入、任务切换、Diff 展示和测试结果切换补真实组件/DOM 测试。
- 使用隔离的 mock transport 驱动 UI，覆盖迟到响应；不把调用纯模型函数等同于交互通过。
- 按现有测试工具选择最小可用 DOM 或浏览器自动化支持，不同时引入多套测试框架，不重写已有 100 多项逻辑测试。
- 如发现重复轮询或状态覆盖，仅收敛该调用链；不因报告提到技术债就全仓替换状态管理。

验收：自动化实际执行输入、点击和断言渲染结果；换 Run 后旧测试输出不能覆盖新 Run；发送失败草稿仍可重试；本台操作不改变其他工作台选择。

### MC-06 / P1 — 离线门禁与真实任务评测交接

依赖：MC-01～05。

- 完成受影响 Python 回归、Desktop typecheck/test/build；最后跑一次既有完整离线门禁，新增变更或失败才触发额外复跑。
- 固定三个候选任务的项目版本、工作目录副本、明确需求、验收命令和允许操作，准备给真实测试执行者的逐步说明。
- 将结果分开：Runtime 合同是否成立、能力是否完成需求、Provider/环境是否失败。旧的 20/24 只能作历史参考，不能直接当本版基线。
- 真实任务结果回来后，按失败证据决定是否需要上下文修正、模型选择或新的工具能力；未得到证据前不把这些扩展列为本轮必做。

验收：离线链路能复跑；每项验证记录实际执行范围与结果。真实模型与 Tauri 项目验收未运行时，交付状态为“代码/离线完成，真实评测待执行”，不写“产品已可靠”。

## 5. 排期与停止条件

顺序：MC-01 → MC-02/MC-03 → MC-04 → MC-05 → MC-06。MC-04 的证据字段设计可在失败用例固定后提前进行。

每张单提交实际改动、根因回归和结果，停止于该合同满足；不要求额外框架、兼容分支或重复审计来证明完成。若现有实现已经满足某条，保留验证结果并关闭该条，不为“有代码产出”而重构。

本轮已确认的自主范围不包括安装依赖、提交和推送；需要这些动作时展示具体请求再确认。不得把临时安装失败转换成另一个自动安装入口。

## 6. 测试边界与后续决策

本项目负责代码和基础离线测试。离线运行屏蔽 OPENAI_API_KEY、LLM_API_KEY、P2_SECONDARY_API_KEY，强制 Ollama；模型测试使用假端点或确定性不可达端点，避免 `.env` 触发真实 DeepSeek。

真实评测由独立执行者在授权环境完成：默认优先本地 Ollama；只有明确需要 DeepSeek 能力并获授权时使用真实 API。测试专用角色只记录证据，不修改生产代码。Tauri/WebView、真实项目构建与用户操作单列验收，离线测试不能替代。

真实评测表至少包含：项目提交/工作树状态、模型与配置、任务输入、预期验收、实际命令和结果、最终文件证据、人工介入、失败归因、未完成项。安装依赖所需环境应事先准备或按用户确认流程处理。

后续候选不承诺排期：Mercury 浏览器操作、Saturn 常驻运行、ReMe 完整遗忘、上下文增强、模型路由、Neptune 生成。完成本轮证据评估后，再由用户选择下一主线。
